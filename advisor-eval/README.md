# Advisor Strategy Evaluation Framework

Evaluate whether **dynamic advisor-based model routing** can achieve strong-model
accuracy at a fraction of the cost and latency by pairing a cheap executor
(GPT-4.1-mini) with a strong advisor (GPT-4.1) that is consulted only when needed.

Inspired by [Anthropic's Advisor Strategy](https://claude.com/blog/the-advisor-strategy).

## Setup

```bash
pip install -r requirements.txt
```

Set your OpenAI API key:

```bash
export OPENAI_API_KEY="sk-..."
```

## Quick Start (MVP)

Run the three core methods on 50 GSM8K samples:

```bash
python run.py --dataset gsm8k --method cheap --samples 50
python run.py --dataset gsm8k --method strong --samples 50
python run.py --dataset gsm8k --method advisor --policy model_driven --samples 50
```

Then analyse the results:

```bash
python run.py --analyze results/
```

## CLI Reference

```
python run.py [OPTIONS]

Options:
  --dataset {gsm8k,hotpotqa}   Dataset to evaluate on (default: gsm8k)
  --method  {cheap,strong,advisor}  Run mode (default: advisor)
  --policy  POLICY              Escalation policy for advisor method
                                Choices: model_driven, self_eval, fixed_interval,
                                         random_prob, failure_based
                                Default: model_driven
  --samples N                   Number of tasks to evaluate (default: 50)
  --config  PATH                Path to config.yaml (default: config.yaml)
  --all                         Run all experiments (1-5)
  --analyze DIR                 Run analysis on existing results directory
  --cache                       Enable disk caching of API responses
```

## Run All Experiments

```bash
python run.py --all --samples 100
```

This runs:
1. **Core comparison** — cheap-only vs strong-only vs advisor (model_driven)
2. **Policy comparison** — all 5 escalation policies
3. **Threshold sweep** — self_eval at thresholds 0.3–0.9
4. **Difficulty split** — computed during analysis from Experiment 1 results
5. **Ablation** — advisor loop with no advisor calls (retry-only)

## Escalation Policies

| Policy | How it works |
|---|---|
| `model_driven` | Executor emits `[REQUEST_ADVISOR]` when it needs help (Anthropic-style) |
| `self_eval` | Executor rates confidence; escalate if below threshold |
| `fixed_interval` | Escalate every N steps |
| `random_prob` | Escalate with probability p each step |
| `failure_based` | Escalate on empty output, invalid format, or repeated answers |

## Configuration

Edit `config.yaml` to change models, cost rates, thresholds, and limits.

## Output

- **Results**: `results/` — one JSONL file per experiment run
- **Plots**: `plots/` — PNG charts generated by analysis
  - `three_axis_summary.png` — accuracy, cost, latency grouped bars
  - `cost_vs_accuracy.png` — scatter
  - `latency_vs_accuracy.png` — scatter
  - `cost_vs_latency.png` — Pareto frontier (color = accuracy)
  - `latency_distribution.png` — box plots
  - `policy_comparison.png` — grouped bars per policy
  - `difficulty_split.png` — recovery rate + hard task latency

## Key Metrics

- **Accuracy**: exact match (GSM8K numeric, HotpotQA case-insensitive string)
- **Cost**: per-token pricing from config, split into executor/advisor
- **Latency**: wall-clock `time.perf_counter()` per API call, split into executor/advisor
- **Advisor usage**: call count and % of steps escalated
- **Recovery rate**: fraction of hard tasks (cheap failed) that advisor fixed
